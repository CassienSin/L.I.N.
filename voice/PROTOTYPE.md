# Lin's English conversation workspace

This is a functioning local conversation prototype built around the selected A voice. It captures English speech on explicit request, transcribes it locally for review, answers the reviewed or typed request through a local model, and speaks the answer. It also searches the dedicated Lin Brain folder with exact passage references, stores explicit lasting memories, and displays both in a live interactive brain map. The spoken-response card follows real audio playback. Accounts and general execution tools are not connected.

## Open and close

Run `Start-LinVoice.ps1` from the project root in PowerShell. It starts hidden local processes and opens the conversation workspace in your browser. Running it again reuses an existing session. Wait for local voice and reasoning to become ready. Use **Unload Lin and close session** to release the models and discard session context. Merely closing a browser tab keeps the service warm. The native reasoning child is attached to a Windows job so it also exits if the Python owner dies unexpectedly.

The launcher requires the existing `.venv-voice`, downloaded model, and NVIDIA driver. It relies on this computer's bundled Python runtime and is not a portable installer. The application binds to an available port on `127.0.0.1`; its session link is recorded in the ignored `voice/runtime/session.json` file. Open that session link, not a guessed port. Do not share it. No system service, startup task, or firewall exception is installed.

## Controls

- **Talk to Lin:** request browser microphone permission and start a recording. **Finish & transcribe** closes the microphone and transcribes locally. Recording also stops automatically at 30 seconds.
- **Discard / Escape:** discard the current recording or pending transcript. Leaving the page also discards active capture. No microphone is opened on page load.
- **Use as my request:** copy the reviewed or edited transcript into the request box. This does not submit it. **Ask Lin** sends it to the local model, displays the answer, and starts voice synthesis. Typed requests use the same flow.
- **Clear conversation:** remove the current conversation from future context and clear its displayed request, transcript, and replay audio. Interrupt active work and wait for computation to settle first. This is context removal, not a forensic memory wipe.
- **Voice preview → Speak with Lin:** read the entered English text using A's synthetic reference, without reasoning.
- **Play saved introduction:** play three already generated example clips. This is cached playback, not a measure of new-text synthesis.
- **Pause / Resume:** hold playback at its current position, including when the next sentence is still being prepared.
- **Interrupt / Escape:** stop sound immediately. The current GPU operation may finish internally, but its result is discarded and remaining sentences are skipped.
- **Replay:** play the audio already received, without generating it again. After an interruption this may be only part of the original text.
- **Mute:** silence playback while its position continues advancing.
- **Search my brain:** choose this mode or begin the request with “Search my brain”. It searches saved memories and the dedicated notes folder, reads a bounded excerpt from the top match, and shows up to three matching source cards. This is exact passage retrieval, not a model-generated document summary.
- **Remember this: …:** prepare an editable fact in Brain & memory. Review its title, content, and personal/business scope, then click **Save memory**. The phrase itself does not commit a write.
- **Brain & memory:** save, edit, inspect history, or forget a fact; open the fixed notes folder; refresh notes; disconnect or reconnect that folder. The global **Interrupt Lin** button also works while this view is open.

Each sentence has an audio buffer and a matching card entry. The `playing`, `ended`, `pause`, and `waiting` events control state and sentence changes. Progress follows the media clock, and the ring/waveform reads the actual audio signal. Reduced motion removes the reactive movement. This provides sentence-level synchronization, not word-level forced alignment.

## Local data and boundaries

The browser loads its scripts, styles and audio from the loopback service only. API requests require a random session token; the server checks Host and Origin and exposes only allowlisted assets and job audio. The token is passed in the launch fragment, removed from the visible URL, and retained in that tab's session storage. No CORS access is granted.

The Python process uses local model paths, offline library settings, disabled telemetry, and blocks outgoing socket connections except the exact service-owned 127.0.0.1 reasoning port. No request can select that destination. The native runtime uses a local GGUF, an offline flag, a private API key, disabled web UI/MCP proxy/slot monitoring, and disabled logging. Inherited llama-specific environment settings are stripped. This is an application guard, not an OS firewall or a packaged production security boundary. No external inference endpoint exists in the prototype. Model downloads happen only through the separate, explicitly run setup script.

Custom requests, answers, synthesis text, and audio stay in bounded process memory: up to eight recent jobs, 24 custom cached audio segments, and eight conversations with at most two recent exchanges and a 2,500-character history budget each. The browser gives each tab a conversation ID; no chat history is written to disk. Closing the service discards this context. Clear removes its conversation history and associated jobs and clears custom speech cache; immutable public demo clips remain available. Native model buffers may retain bytes until overwritten or unloaded; this is not secure memory erasure.

Microphone recordings are limited to 30 seconds and 2 MB, decoded in memory, and never written as recording history. A discarded in-flight transcription may finish computing, but its result cannot populate the UI. Explicitly saved facts and the selected-folder index persist as described below; ordinary chat and custom audio do not. Public example/benchmark data is also persisted. Runtime launch data and logs are ignored by version control; request text and tokens are not logged. Generation errors are visible instead of being replaced with sample speech.

## English microphone transcription

Recognition uses faster-whisper 1.2.1 with the English-only `base.en` model from SYSTRAN, CPU int8, and four CPU threads. It uses a pinned local model directory and voice-activity filtering, with no browser/cloud speech-recognition API. The model revision and checksums are recorded in `transcription-model-source.json`; dependencies are included in `requirements-gpu-lock.txt`. This keeps recognition off the GPU used by Lin's voice.

Three existing synthetic English clips (2.68–3.84 seconds) transcribed in 0.94–1.24 seconds on this computer. All words matched the scripts; punctuation differed in one clip. A browser capture test using a synthetic microphone fixture reached transcript review in 1.38 seconds after Finish. These are quiet synthetic fixtures, not a test of the user's microphone, accent, noise, names, or mixed-language speech. Filipino and Cebuano recognition are not supported by this English-only model.

The browser supplies WebM/Ogg recordings over authenticated loopback requests. The server checks file size, decoded duration, allowed audio formats, and concurrent transcription. Silence produces no transcript in the fixture test. Recognition can still make mistakes; the editable review step is intentional. If the app's browser panel cannot grant microphone access, run the launcher in Edge or Chrome. Actual microphone permission remains the user's choice.

Permission recovery: if capture is denied or unavailable, the workspace shows **Open Lin in browser**, plus guidance for page permissions and Windows microphone privacy. The button opens only the current authenticated local session in the Windows default browser; it cannot open a caller-supplied URL and never grants permission or starts recording. The user still presses Talk to Lin and approves the browser's prompt. The supplied screen recording showed the permission-denied message and a timer remaining at zero; this establishes a capture-permission failure, but does not identify whether the cause is the embedded browser, site settings, or Windows. The recovery flow has automated denial/authorization tests. The user subsequently confirmed actual microphone capture works in their browser. [Microsoft's microphone troubleshooting documentation](https://learn.microsoft.com/en-us/troubleshoot/microsoft-edge/development/edge-camera-microphone-not-working) describes the separate operating-system and browser permission checks.

Sources: [faster-whisper](https://github.com/SYSTRAN/faster-whisper) and the [MIT-licensed converted English model](https://huggingface.co/Systran/faster-whisper-base.en). This recognition model's license does not change OmniVoice's separate noncommercial restriction.

## Validation and remaining work

### Local conversational model

The official [Qwen3 4B GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF) is installed at pinned revision `bc640142c66e1fdd12af0bd68f40445458f3869b`, Q4_K_M, about 2.5 GB, Apache-2.0. The CPU runtime is the official [llama.cpp b11669 Windows release](https://github.com/ggml-org/llama.cpp/releases/tag/b11669), MIT. `reasoning-model-source.json` records exact URLs and SHA-256 hashes; `download_reasoning.py` verifies both before installing. Setup requires internet; inference uses only local files. Neither license changes the separate OmniVoice noncommercial limitation.

`IDENTITY.md` loads at service startup and records Lin's tone, English preference, current capabilities, and limits. Edit it and restart to change her instructions. It is product configuration, separate from explicitly saved facts. Relevant saved memories are retrieved by keywords and supplied as data to the local conversational model. Source cards identify which facts were supplied; they are not proof that every generated claim is supported. The runtime uses six CPU threads, a 4,096-token context, one slot, disabled extended thinking, and at most 180 output tokens. Requests are limited to 1,000 characters, and spoken answers to 580 characters. Exceptionally dense text or unusual tokenization can exceed the model's context and produces an error; the application does not switch providers.

The latest integrated planning request took 12.46 seconds to show its answer and 17.89 seconds to start new speech (an earlier run took 11.69 and 16.82 seconds). Initial standalone examples took roughly 4–9 seconds, with a shorter recall answer around 2 seconds. These are public synthetic prompts and single-run observations, not guarantees. `reasoning-benchmark/integration-results.json` holds the latest full-flow run; `results.json` retains the initial baseline, including an overly hesitant planning answer that led to an identity refinement. Full-answer generation currently precedes speech; streaming the first complete sentence and broader model evaluation remain latency work.

The integration test verifies real local transcription from a synthetic microphone, explicit review without automatic submission, a generated plan, actual speech, pause/resume, interruption during thinking, no late speech, overlap rejection, recent recall, separate conversation IDs, clearing context, unavailable calendar disclosure, and four viewport widths. The Windows lifetime test verifies abrupt owner termination also kills its attached child. Normal session shutdown was separately verified to remove the native model process. Existing speech playback tests pass with the reasoning model loaded. The native transport test also verifies that inference rejects a missing API key, only the exact assigned loopback address is allowed, and that allowance is revoked when the model closes.

The model has no execution tools. A model statement cannot execute code, send messages, modify source files, or save a memory. Deterministic application routes handle exact note lookup and memory previews; authenticated user actions handle writes. Identity instructions guide capability disclosures, but a compact model can still misunderstand or overstate what it can do. Tool policy enforcement must be implemented separately before connecting external actions.

### Lin Brain and durable memory

The user chose a new `Lin Brain` folder in the project. Only that fixed folder is scanned, up to five nested directory levels; dotfiles, linked files/folders and unsupported formats are excluded. UTF-8 `.txt` and `.md` files are supported, at most 200 files, 256 KB per file, roughly 8 MB of decoded content per scan, and 2,000 visited entries. Oversized individual lines are omitted and reported. The UI shows skipped items and incomplete scans. PDF, Word, images, audio, embeddings, and account providers are not supported yet.

Search uses SQLite FTS5 with English stemming and keyword ranking. It can miss paraphrases and return loosely related matches. File lookup quotes the actual passage, with a file path, line range, content hash, and modification timestamp. Clicking a source refreshes from disk before showing it; changed or unavailable passages return a stale-source message. Content hashes detect changes even when a file timestamp is preserved. Notes are rescanned before a new request and every three seconds while inference is idle. Edits, moves, deletions, and disconnection remove old passages from retrieval. Source text is displayed literally and never interpreted as HTML or an executable instruction. The Windows reader validates the final opened file handle's location as well as checking paths and reparse points. The app never edits the original notes.

Data is stored locally in `voice/data/brain.sqlite3`, excluded from version control. It contains explicit memory records, previous versions, current indexed passages and local settings. Memories have a stable ID, title, fact, personal/business scope, revision, and UTC creation/update times. The first release supports 200 active memories, 80-character titles, and 500-character facts. Same-title duplicates within a scope and edits against an outdated revision are rejected. Semantic conflicts under different titles are not automatically detected. Previous versions are viewable in History but are excluded from retrieval. No conversation is mined or saved automatically.

**Clear conversation** removes recent chat, while **Forget** removes the selected durable fact, its edit history, and retrieval entry. Corrections and forgetting also invalidate recent chat, retained answer jobs, and custom audio caches so stale facts are not fed back into the model. Other open tabs clear stale response displays on their next status update. Explicit memories survive service shutdown; temporary chat does not. Disconnecting the folder removes indexed file passages but leaves both original files and explicit memories intact. This local database is not encrypted by Lin, has no automatic backup, and deleting a record is not a promise of forensic erasure from operating-system storage or native model buffers.

`brain-benchmark/storage-results.json` covers persistence, revision conflicts, source line ranges, changed/moved/deleted files, an actual Windows junction, size/encoding limits, and document instructions having no write capability. `integration-results.json` covers the browser memory review/save flow, local generated recall with voice, history, source cards, disconnect/reconnect, small screens, correction across an actual service restart, forgetting, and removal of temporary test data. `freshness-results.json` checks that newly valid citations survive a revision update while later edits clear stale cards. Only synthetic verification facts were used; they were removed afterward.

`gpu-benchmark/results.json` records six real GPU synthesis runs. `gpu-benchmark/integration-results.json` records browser tests covering playback, pause/resume, mute, replay, interruption, sentence transitions, fresh synthesis, cancellation during generation, rejection of overlapping requests, reduced motion, Escape, four screen widths, request authorization, and absence of external page requests. Desktop and mobile screenshots are under `design/`.

The original auditions accidentally supplied `language_id` to an API that expects `language`; that keyword did not explicitly condition the old samples. The generation script now uses the correct parameter, and the new English adapter passes `language='en'`. Original audition files and measurements remain unchanged. Their stored language IDs represent intended languages, not proof of language conditioning. The user's reported Filipino/Cebuano pronunciation issues remain unresolved.

`transcription-benchmark/` records CPU recognition measurements and the synthetic browser-capture checks. Coverage includes capture only after a click, stopped microphone tracks, permission denial, cancellation while permission is pending, discard, page hiding, transcript editing and voice read-back. The existing voice regression checks also pass with microphone support present. The user confirmed real microphone capture works. Recognition quality across accents, noise, names, and longer requests still needs evaluation.

The model's noncommercial restriction still applies; this is personal evaluation, not the business-production engine. A's original clip is retained unchanged. Reference transfer and GPU numerics can alter delivery, so the new English voice still merits listening review. Next production gates are appropriate licensing, longer English/name/number tests, broader microphone quality evaluation, and lower conversational response latency.

## Live brain map · 22 October 2026

The **Brain map** tab visualizes actual indexed files and explicitly saved memories. Its authenticated `/api/brain/graph` endpoint provides compact metadata and membership edges. File identities remain stable across edits, while passage IDs change with content. Source text is fetched through the existing authenticated source endpoint when selected, never interpolated as HTML. The map uses deterministic SVG placement with no idle simulation or decorative motion. Larger collections spread farther apart and suppress unselected labels above 35 visible items. ## Plan my day · 22 October 2026

The Plan my day tab provides explicit local task creation, editing, done/reopen, and removal. It stores up to 200 tasks in `voice/data/planner.sqlite3`, separately from durable facts and the notes index. Tasks have personal/business scope, High/Normal/Low priority, and a 1–480 minute estimate. Settings allow 5–480 available minutes, a break between tasks, and a scope filter. Completed tasks remain saved but are excluded from plans. Tasks are not automatically reset at midnight.

The deterministic planner orders open tasks by priority, then creation time and ID. It includes whole tasks that fit, counting breaks only between included tasks. Skipped tasks remain visible with an explanation; shorter, lower-priority tasks may fill the remaining time. Displayed ranges are elapsed minutes from the start of a focus session, not wall-clock appointments. The UI and spoken summary identify unused time and excluded work. Actual task durations depend on the user's estimates. No calendar, inbox, deadline, recurrence, or reminder integration is implied.

The exact reviewed or typed request “Plan my day” (optionally prefixed with “please”) opens the planner instead of generating a conversational answer. Hear my plan sends only the saved plan revision to the authenticated local speech endpoint. The server validates that revision and generates the spoken text from current saved tasks, summarizing up to three tasks and referring to the remaining card items. Playback uses Lin A and the existing synchronized sentence cards; it continues across workspace switches. A newer planner revision clears stale replay and interrupts an older plan summary. Unsaved planning settings disable Hear my plan until applied. The conversational model itself has no task-list access or task-writing tools.

Task and preference writes use optimistic revision checks. Stale writes and stale speech requests are rejected; failed writes do not claim success. Existing local authentication, origin checks, and busy-state controls apply. The task database is local, unencrypted, and excluded from source control; automatic backups remain unimplemented.

Validation: `voice/verify_planner.py` covers persistence, exact budget/break arithmetic, ordering, scope, deferred work, corrections, done/reopen, removal, invalid/stale writes, and 250 seeded random plans. `design/verify-planner.cjs prepare` checks browser controls, narrow layouts, actual voice playback, stale replay clearing, and the phrase trigger. After a real service restart, its `resume` phase verified saved tasks/settings and removed all temporary test tasks while restoring prior preferences. Results: `voice/brain-benchmark/planner-results.json`. The screenshots `design/planner-desktop.png` and `design/planner-mobile.png` show explicitly labeled test fixtures, which were removed after validation.

## Today briefing · 22 October 2026

## Streaming answers · 22 October 2026

`LocalReasoner.answer()` accepts `on_sentence`; `server.sentence_sink()` appends each finished sentence to the job and hands the job to the voice at the first one. The voice worker waits for further sentences while `job['streaming']` is set. Tool answers pass each sentence through `actions.verify_answer()` before it is queued. Cancellation stops both generation and speech, and a cancelled partial answer is not saved to chat history. The eight-segment bound still applies. `LocalReasoner.warm()` pre-reads the identity prompt into slot 0 and the router prompt into slot 1 at startup (`REASON_STATE['warm_seconds']`). Jobs report `first_text_seconds` and llama.cpp `timings` (prompt, cached and generated tokens with milliseconds) for both routing and answering.

Validation: `voice/verify_streaming.py` runs the real reasoning and voice workers with stand-in engines (speech before generation ends, ordering, per-sentence verification, summary fallback, missing-source handling, interruption, the sentence bound; `brain-benchmark/streaming-results.json`). `design/probe-latency.cjs` (`Run-LatencyProbe.cmd`) measures each stage on the running Lin (`latency-results.json`).
